Wejście z rzeczywistego pliku: WPF i CLI oraz filtrowanie drzewa

Aplikacja analizuje pliki .dll/.exe wskazane przez użytkownika — w WPF przez okno wyboru pliku, w CLI przez argument wiersza poleceń — a drzewo metadanych można filtrować po nazwie. Dane symulowane pozostają dostępne jako osobna, jawna akcja.

1. Wybór pliku w WPF

  • MainViewModel.UseAssemblyPicker(Func<string?>) — widok wstrzykuje okno wyboru pliku, ViewModel pozostaje wolny od System.Windows.Forms.
  • OpenAssemblyCommand pyta o plik i wywołuje AnalyzeAsync(new MetadataSource(path), token); anulowanie okna daje status Open cancelled. bez wywołania usługi.
  • MainWindow.PickAssemblyFile() — OpenFileDialog z filtrem *.dll;*.exe, katalogiem startowym AppContext.BaseDirectory i sprawdzaniem istnienia pliku.
  • Menu File zawiera teraz jawną pozycję Load Sample Assembly — dane symulowane nie są już efektem ubocznym Open.
  • MainViewModel.LoadSampleAsync przekazuje MetadataSource.Empty, więc nie zależy od okna wyboru.

2. Argument ścieżki w CLI

  • Program.Main wybiera pierwszy argument niebędący przełącznikiem (-/--) i przekazuje go do MetadataConsoleApp.RunAsync(path, token).
  • Analiza wykonuje się przed wyświetleniem menu; nieudane wczytanie kończy się komunikatem Analysis failed: … i kodem wyjścia 1.
  • Logowanie nieoczekiwanego wyjątku przechodzi przez LogErrorAsync("Unhandled CLI failure", exception), więc łańcuch przyczyn trafia do pliku logu.
dotnet run --project MetadataAnalyzer.CLI -- "C:\libs\SampleAssembly.dll"
Assembly analyzed: SampleAssembly 1.0.0.0
Location:      C:\libs\SampleAssembly.dll
Namespaces:    1
Types:         8

3. Filtrowanie drzewa metadanych

  • MainViewModel.SearchText (z UpdateSourceTrigger=PropertyChanged) filtruje drzewo po każdej zmianie; HasSearch steruje przyciskiem Clear, a status pokazuje liczbę trafień.
  • TreeNodeViewModel.IsVisible + DataTrigger w AssemblyTreeViewItemStyle ukrywają niepasujące węzły (bez łamania szablonu kontrolki).
  • TreeNodeViewModel.ApplyFilter(text, expandMatches) zwraca liczbę trafień i rozświetla ścieżkę do dopasowań; przy filtrowaniu z UI (expandMatches: false) nie zmienia stanu rozwinięcia, więc czyszczenie filtra przywraca poprzedni widok.
  • AssemblyViewModel.ApplyFilter(null) czyści filtr i zeruje licznik; filtr jest ponownie stosowany po każdym wczytaniu assembly.
